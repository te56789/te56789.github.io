1. Before you report

Two checks solve most reports:

  • Open the health check page in the application. It reports what the application can and cannot reach on this machine — the data folder, git, and whether the local model service answers.
  • If an agent step failed: for a local model, confirm the Ollama service is running and that the model name in the step is written as ollama/<model>; for a cloud model, confirm that the provider's API key is stored in the vault (Settings).

2. Report a bug

Send the report to linsevenlight@gmail.com with the subject line [ai-team-os] bug.

待補 — a public issue tracker will be linked here once it is open.

Please include:

  • ai-team-os version (shown in the application);
  • Windows version and edition;
  • the step kind that failed — command, write_file, git_commit, agent, http or browser;
  • the run identifier, if the failure happened during a run;
  • steps to reproduce, starting from a fresh launch;
  • what you expected, and what happened instead;
  • relevant error messages, with secrets removed.

Never include API keys, access tokens, passwords, webhook URLs, private prompts, personal information or confidential project content. Replace anything sensitive with a placeholder before sending.

3. Report inappropriate AI-generated content

An agent step generates text with a model. That output is not reviewed in advance and can be inaccurate, offensive or otherwise unsuitable. If you receive AI-generated content you consider inappropriate, report it.

How to report, from inside the application: main window → Privacy, support and reporting → Report inappropriate AI output.

  1. Pick one of six reasons: dangerous, hateful, sexual, deceptive, privacy-related, other.
  2. Optionally fill in the run identifier and the step identifier, and write a short note about what happened.
  3. Press preview what will be sent. The complete payload is shown before anything is written, together with a list of what was removed from your note.
  4. Press produce the report file. You get a report identifier (a UUID) and a file at <data folder>\reports\ai-report-<id>.json (the data folder is %APPDATA%\ai-team-os for the installer build, %USERPROFILE%\.ai-team-os for the Store build).

A report carries identifiers only — report id, timestamp, application version, reason, run id, step id and your note. It carries no prompt, no file content, no conversation and no credential. Your note is scrubbed of anything shaped like an API key, an e-mail address, a URL, a Windows or UNC path, or a run of 32 or more characters, and it is truncated at 500 characters.

This release has no reporting server. A button that pretends to have sent something is worse than no button, so the application produces a file and says so. Attach that file to an e-mail to linsevenlight@gmail.com with the subject line [ai-team-os] AI content report. If you cannot open the application, send the same details by e-mail directly.

What happens next. Each report gets a reply quoting its report identifier. Reports are triaged by severity, and the outcome is recorded and sent back to you. Where the problem comes from the model service you configured rather than from ai-team-os, the reply will say so and point to that service's own reporting channel.

4. Security vulnerabilities

Email linsevenlight@gmail.com with the subject line [ai-team-os] security. Please do not post a vulnerability in a public thread before it has been fixed. Describe the issue, the affected version, and the impact; a proof of concept is welcome but must not contain real secrets.

5. Privacy questions

See the privacy policy. In short: the application runs locally, has no account, sends no telemetry, and sends data only in ways you set up yourself: task steps you wrote, chats with a cloud model, notifications you switched on, and update checks you run. Questions to the same address, subject line [ai-team-os] privacy.

6. Known limitations

LimitationDetail
The two distribution channels do not share a data folder The installer build keeps its data in %APPDATA%\ai-team-os. The Microsoft Store (MSIX) build keeps its data in %USERPROFILE%\.ai-team-os instead, because MSIX virtualises writes to %APPDATA% and deletes them on uninstall. If you move from one channel to the other, the new build starts with an empty data folder: it does not see your existing vault, runs or artifacts. Use npm run backup to carry them across, or point TEAMOS_HOME at the folder you want both builds to use.
No model is bundled for agent steps The application does not bundle or install any model. A local model needs Ollama installed and running, with the model written as ollama/<model>. A cloud model needs that provider's API key stored in the vault; the provider bills you for its use, and the step's data goes to that provider (see the privacy policy).
Microsoft Edge required for browser steps Browser steps use Playwright driving the Edge already installed on the system. No browser binary is downloaded. Without Edge, browser steps cannot run.
No code signing on the direct-download channel Builds published in the public releases repository are not signed with a code-signing certificate, so Windows SmartScreen warns on first run. The Microsoft Store copy is signed by Microsoft during certification and does not produce that warning.
Windows 10 / 11, x64 only No ARM64 build, no macOS build, no Linux build.
Single user, single machine No cloud sync, no shared workspace, no team accounts, no remote administration.
No plugin or module marketplace A task specification is data, not code. There is no third-party extension mechanism and no add-on store.
browser steps take verbs, not scripts Six verbs only: goto, click, fill, read, wait, screenshot. Arbitrary browser scripting is not accepted.
Updates are not installed automatically The update check tells you a newer version exists. It does not download or install it for you. This is deliberate.

7. Versions and updates

  • Current version: 0.1.0.
  • Microsoft Store channel: updates arrive through the Store once a new submission is published.
  • Direct-download channel: the application checks whether a newer release exists and tells you. You download and install it yourself.
  • Before updating: the application supports backup and restore of its data folder, and the data folder carries a version of its own so an upgrade knows what it is reading. Taking a backup before a version change is recommended.

一、回報之前先做兩件事

大部分的回報，這兩步就能解決：

  • 先開程式裡的體檢頁。它會列出在這台機器上，哪些東西接得到、哪些接不到 —— 資料家、git，以及本機模型服務有沒有回應。
  • 如果是 agent 步驟失敗：用本機模型的話，確認 Ollama 服務有在跑，而且步驟裡的模型名稱寫成 ollama/<模型名>；用雲端模型的話，確認那一家的 API 金鑰已經存進 Vault（在設定頁）。

二、回報問題

寄到 linsevenlight@gmail.com，主旨開頭寫 [ai-team-os] bug。

待補 —— 公開的問題追蹤頁開放後會放在這裡。

請附上：

  • ai-team-os 版本（程式裡看得到）；
  • Windows 版本與版本類型；
  • 出問題的步驟種類 —— command、write_file、git_commit、agent、http 或 browser;
  • 如果是執行途中出事，附上該次執行編號；
  • 從重新啟動程式開始算的重現步驟；
  • 你預期會發生什麼、實際發生了什麼；
  • 相關的錯誤訊息，祕密的部分先拿掉。

絕對不要附上API 金鑰、存取 token、密碼、webhook 網址、私人 prompt、個人資料或機密專案內容。敏感的部分寄出前先換成佔位符號。

三、回報不當的 AI 生成內容

agent 步驟會用模型即時產生文字。那些輸出沒有經過事前審閱，可能不正確、可能冒犯人、也可能不適合。如果你收到你認為不當的 AI 生成內容，請回報。

怎麼回報，直接在程式裡做：主畫面 →「隱私、支援與回報」→「回報不當的 AI 產出」。

  1. 從六個理由裡選一個：危險或可能造成傷害、仇恨或騷擾、性內容、詐騙或誤導、隱私、其他。
  2. 可以補上該次執行編號與步驟編號，再寫幾句說明。
  3. 按「先看會送出什麼」。整份內容會在任何東西被寫下來之前顯示出來，並列出你的說明裡有哪些片段被洗掉。
  4. 按「產生回報檔」。你會拿到一組回報編號（UUID），檔案在 <資料夾>\reports\ai-report-<編號>.json（安裝檔版本的資料夾是 %APPDATA%\ai-team-os，商店版是 %USERPROFILE%\.ai-team-os）。

一筆回報只帶編號 —— 回報編號、時間、程式版本、理由、執行編號、步驟編號，以及你寫的說明。沒有 prompt、沒有檔案內容、沒有完整對話、沒有憑證。你寫的說明還會再洗一次：看起來像 API 金鑰、電子郵件、網址、Windows 或 UNC 路徑的片段，以及 32 字以上的連續字串，一律換掉，超過 500 字截斷。

這一版沒有回報伺服器。一個「假裝已經送出去了」的按鈕，比沒有按鈕更糟，所以程式產生的是一個檔案，而且會直說。把那個檔附在信裡寄到 linsevenlight@gmail.com，主旨開頭寫 [ai-team-os] AI content report。如果你打不開程式，直接把同樣的內容寫在信裡寄過來也可以。

後續怎麼處理。每一筆回報都會回信並引用它的回報編號。回報依嚴重程度分級處理，處置結果會記錄下來並回覆給你。如果問題來自你自己設定的模型服務、不是來自 ai-team-os，回信會說明，並指出該服務自己的回報管道。

四、安全漏洞

寄到 linsevenlight@gmail.com，主旨開頭寫 [ai-team-os] security。修好之前請不要把漏洞貼在公開討論串。請描述問題、受影響的版本與影響範圍；歡迎附概念驗證，但裡面不可以有真實祕密。

五、隱私問題

請看隱私權政策。簡短講：這支程式跑在本機、沒有帳號、不送遙測，資料只會從你自己設定好的地方送出去：你寫的任務步驟、你跟雲端模型的對話、你打開的通知，以及你按下的檢查更新。有問題寄同一個信箱，主旨開頭寫 [ai-team-os] privacy。

六、已知限制

限制說明
兩條通路的資料夾不共用 安裝檔版本的資料放在 %APPDATA%\ai-team-os；Microsoft Store（MSIX）版本放在 %USERPROFILE%\.ai-team-os。會分開是因為 MSIX 會把寫進 %APPDATA% 的東西虛擬化，而且解除安裝時一起刪掉。所以你如果從一條通路換到另一條，新版本會從一個空的資料夾開始 —— 看不到你原本的金鑰、執行紀錄與產物。要帶過去請用 npm run backup，或是用 TEAMOS_HOME 讓兩邊指到同一個資料夾。
agent 步驟不附模型 本程式不內含、也不會幫你安裝任何模型。用本機模型要先裝好 Ollama 並讓它跑著，模型寫成 ollama/<模型名>。用雲端模型要把那一家的 API 金鑰存進 Vault；費用由那一家向你收，步驟的資料也會送到那一家（見隱私權政策）。
browser 步驟需要 Microsoft Edge 瀏覽器步驟是用 Playwright 驅動系統上已經裝好的 Edge，不會另外下載瀏覽器。沒有 Edge 就跑不了瀏覽器步驟。
直接下載的通路沒有程式碼簽章 公開釋出倉庫發佈的版本沒有用程式碼簽章憑證簽，第一次執行時 Windows SmartScreen 會跳警告。Microsoft Store 的版本在認證過程中由 Microsoft 簽署，不會有這個警告。
只支援 Windows 10／11 x64 沒有 ARM64 版、沒有 macOS 版、沒有 Linux 版。
單人單機 沒有雲端同步、沒有共用工作區、沒有團隊帳號、沒有遠端管理。
沒有外掛或模組商店 任務規格是資料，不是程式。沒有第三方擴充機制，也沒有附加元件商店。
browser 步驟收動詞，不收腳本 只有六個動詞：goto、click、fill、read、wait、screenshot。不接受任意瀏覽器腳本。
更新不會自動安裝 更新檢查只會告訴你有新版本，不會幫你下載或安裝。這是刻意的。
