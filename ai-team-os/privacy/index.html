English

In one paragraph. ai-team-os runs entirely on your own Windows PC. There is no account, no sign-in, no developer-operated server and no telemetry — the developer receives no data from the application at all. Data leaves your computer only when a task step that you wrote yourself tells it to, and only to the destination you named in that step. Everything else stays in one local folder that you can delete at any time.

1. Scope

ai-team-os ("the application") is a Windows desktop application published by te56789. This policy describes how the application handles data on the user's own device. It applies to the copy distributed through the Microsoft Store and to builds distributed from the project's public releases repository.

2. No accounts, no cloud service

The application has no sign-in, no user account and no developer-operated server. The developer does not host, receive or store user content. There is no cloud sync, no multi-user collaboration and no remote administration.

3. No telemetry

The application sends no usage data, analytics, crash reports or diagnostic pings to the developer. The telemetry package in the source tree is intentionally empty. There is no analytics setting to turn off, because nothing is collected.

4. What is stored on your device

All application data lives in one local data folder. By default that folder is %APPDATA%\ai-team-os for the installer build, and %USERPROFILE%\.ai-team-os for the Microsoft Store (MSIX) build — the Store build deliberately keeps its data outside %APPDATA% so that uninstalling the app never deletes it. You can move it by setting the TEAMOS_HOME environment variable. The folder contains:

  • vault\vault.db — stored credentials, encrypted with Windows DPAPI under your Windows user account;
  • runs\runs.db — run records, step events, the cost ledger and task-specification versions;
  • an artifact content store — the files and outputs produced by task steps;
  • a project register — the projects and git worktrees you have registered;
  • platform.json — application settings;
  • browser sign-in state used by browser steps, encrypted with Windows DPAPI;
  • reports\ — the reports you create with “Report inappropriate AI output”, one JSON file each. They stay on your device until you choose to send one.

No part of this folder is transmitted anywhere by the application.

5. What can leave your device, and only when you ask for it

A task specification is data that you author: you define the steps in the task builder or import them as JSON, and the application executes them. Exactly three step kinds can send anything off the machine, and each one sends it to a destination that you wrote into your own specification.

Step kindWhat is sentWhere it goes
agent The prompt text and the project context you selected. The model service you configured. In this release the agent step only accepts models addressed as ollama/<model>, served by a local Ollama installation on the same machine — so in the default configuration this data does not leave the computer.
http The request you defined in the step. The URL you wrote in the specification.
browser The navigation, and whatever the six permitted verbs do on the page you named. The host you wrote in the specification. Three separate host-allowlist checks run before a navigation is performed.

The content sent is the content you placed in the specification: prompt text, the files you selected, and the project context you selected. The application does not scan your drive, does not upload files you did not reference, and does not add data of its own to these requests.

6. Credentials

Credentials are held in a local vault encrypted with Windows DPAPI and tied to your Windows user account. The vault supports three profile layers — system, user and project — and credential rotation. Plaintext secrets are never written to logs, never rendered in the user interface and never placed on a command line.

You may choose to store credentials for third-party services. The kinds of credential the vault can hold include API keys for DeepSeek, Meta/Llama, DashScope/Qwen, Z.ai/GLM, Gemini, OpenAI and Anthropic services, and notification webhook URLs of the kind used by Telegram or Slack. A webhook URL is itself a secret and is stored as one.

None of these services is enabled by default, and ai-team-os is not affiliated with, endorsed by, or an official client of any of them. Storing a credential does not by itself transmit anything: a credential is used only when a step you wrote calls the service it belongs to.

7. Third-party services you configure

When a step you wrote sends data to a third-party service, that service's own terms and privacy policy govern what happens to the data. Review them before configuring a service. The developer of ai-team-os has no visibility into and no control over that processing.

8. Files

The application reads and writes files inside the projects you register and inside its own data folder. A write_file step writes where the specification says to write. A git_commit step commits in the git worktree assigned to that seat. Files are read only when a step you wrote refers to them. The application never uploads the contents of your drive.

9. Local commands

A command step runs a command line that you wrote into the task specification, on your machine, under your Windows account. The application does not download programs and run them, and does not fetch code from the internet to execute. High-risk actions stop and wait for your approval before running; an action beyond its granted permission level is refused and produces no side effect.

10. Live generative AI

An agent step produces text generated by a model in response to your prompt. Generated output is not reviewed by the developer before you see it, and it can be inaccurate, offensive or otherwise unsuitable. Do not rely on generated output without checking it.

You can report inappropriate AI-generated content from inside the application: main window → Privacy, support and reporting → Report inappropriate AI output. Pick a reason, optionally add the run and step identifiers and a short note, then press preview what will be sent to read the exact payload before anything is written.

A report carries identifiers only — report id, timestamp, application version, reason, run id, step id and your note. It carries no prompt, no file content, no conversation and no credential. Your note is additionally scrubbed of anything that looks like an API key, an e-mail address, a URL, a Windows or UNC path, or a long unbroken string, and it is truncated at 500 characters; the application shows you what it removed.

The report is written as a file in reports\ inside your data folder. This release has no reporting server, so nothing is transmitted: you decide whether to send that file to the support address. The support page describes the same route for anyone who cannot open the application.

11. Data sharing and sale

The developer receives no user data, and therefore shares none and sells none. Data goes only to the destinations named in your own task specifications.

12. Retention and deletion

Everything is kept locally, and kept until you delete it. Deleting the data folder removes all application data, including the vault, run history, cost ledger and artifacts. Backup and restore is manual and is triggered by you; a backup is written where you tell the application to write it. There is no server-side copy for you to request the deletion of.

13. Your controls

  • Delete the data folder, or any file inside it, at any time.
  • Remove or rotate any stored credential.
  • Decide which steps exist in a task. A step you do not write never runs.
  • Approve or refuse each high-risk action at the approval gate.
  • Leave unattended mode off; it is off by default. Unattended mode can schedule work, retry when quota returns and resume after a crash, but it approves nothing — it stops at every approval gate.
  • Set a budget ceiling so a run stops at a cost you chose.
  • Open Privacy, support and reporting at any time to see, computed from the build you are running, which step kinds can send anything off this machine and to where, what is stored locally, and which of it is encrypted.
  • Report AI output you consider inappropriate, and read the exact payload before it is written.

14. Children

ai-team-os is a developer tool and is not directed to children. Third-party services you configure have their own age requirements, which you are responsible for meeting.

15. Changes to this policy

This page is updated when the application's data handling changes. The Last updated date at the top of the page reflects the most recent change.

16. Contact

Email: linsevenlight@gmail.com

Use the same address for privacy questions, security reports and general support. Please do not include API keys, access tokens, passwords or confidential project content in any message.

一、適用範圍

ai-team-os（以下稱「本程式」）是 te56789 發行的 Windows 桌面應用程式。本政策說明本程式在使用者自己的電腦上怎麼處理資料，適用於 Microsoft Store 通路的版本，以及本專案公開釋出倉庫發佈的版本。

二、沒有帳號，也沒有雲端服務

本程式沒有登入、沒有使用者帳號，開發者也沒有架設任何伺服器。開發者不代管、不接收、不保存使用者的內容。沒有雲端同步、沒有多人協作、沒有遠端管理。

三、沒有遙測

本程式不會把使用資料、分析數據、當機報告或診斷訊號送回給開發者。原始碼裡的 telemetry 套件是刻意留空的。這裡沒有「關閉分析」的開關，因為根本沒有收集。

四、存在你電腦裡的東西

本程式的資料全部放在同一個本機資料夾。安裝檔版本的預設位置是 %APPDATA%\ai-team-os；Microsoft Store（MSIX）版本則是 %USERPROFILE%\.ai-team-os —— 商店版刻意把資料放在 %APPDATA% 之外，這樣解除安裝就不會把它一起刪掉。你可以設定 TEAMOS_HOME 環境變數把它搬到別的地方。這個資料夾裡有：

  • vault\vault.db —— 已儲存的憑證，用 Windows DPAPI 綁你的 Windows 使用者帳戶加密；
  • runs\runs.db —— 執行紀錄、步驟事件、費用帳本，以及任務規格的版本；
  • 產物內容庫 —— 任務步驟產生的檔案與輸出；
  • 專案名冊 —— 你登記過的專案與 git worktree;
  • platform.json —— 程式設定；
  • browser 步驟用的瀏覽器登入狀態，同樣用 Windows DPAPI 加密；
  • reports\ —— 你用「回報不當的 AI 產出」建立的回報，一筆一個 JSON 檔。在你決定寄出之前，它們只待在你的電腦裡。

這個資料夾裡的任何部分，本程式都不會往外送。

五、什麼會離開這台電腦，而且只在你叫它送的時候

任務規格是你自己寫的資料：你在「任務建立」畫面定義步驟，或是匯入 JSON，本程式負責照著執行。只有三種步驟會把東西送出這台機器，而且每一種都是送到你自己在規格裡寫的目的地。

步驟種類送出什麼送去哪裡
agent 你的 prompt 文字，以及你選定的專案上下文。 你設定的模型服務。本版的 agent 步驟只認得寫成 ollama/<模型名> 的模型，由同一台電腦上的本機 Ollama 提供 —— 所以在預設設定下，這些資料根本不會離開這台電腦。
http 你在步驟裡定義的那個請求。 你在規格裡寫的那個網址。
browser 導向動作，以及六個許可動詞在你指定的頁面上做的事。 你在規格裡寫的主機。導向之前會先過三道主機清單檢查。

送出去的內容，就是你自己放進規格裡的內容：prompt 文字、你挑的檔案、你挑的專案上下文。本程式不會掃你的硬碟，不會上傳你沒有指名的檔案，也不會自己在這些請求裡加料。

六、憑證

憑證放在本機的 Vault，用 Windows DPAPI 加密，綁定你的 Windows 使用者帳戶。Vault 支援 system、user、project 三層 profile，也支援輪換。明文祕密不會寫進 log、不會顯示在畫面上、不會出現在命令列。

你可以自行選擇要不要存第三方服務的憑證。Vault 能存的憑證種類包含 DeepSeek、Meta/Llama、DashScope/Qwen、Z.ai/GLM、Gemini、OpenAI、Anthropic 等服務的 API 金鑰，以及 Telegram、Slack 這一類的通知 webhook 網址。webhook 網址本身就是祕密，所以也當祕密存。

上面這些服務沒有一個是預設啟用的。ai-team-os 與其中任何一家都沒有隸屬、合作或官方授權關係，也不是任何一家的官方用戶端。存了憑證不等於送出任何東西：憑證只有在你寫的步驟去呼叫它所屬的服務時才會被用到。

七、你自己設定的第三方服務

當你寫的步驟把資料送到第三方服務時，那筆資料之後怎麼處理，由該服務自己的條款與隱私權政策決定。設定前請先讀過。ai-team-os 的開發者看不到也管不到那一段處理。

八、檔案

本程式會在你登記的專案內，以及自己的資料夾內讀寫檔案。write_file 步驟寫在規格指定的位置；git_commit 步驟在那個席次被分配到的 git worktree 裡 commit。檔案只有在你寫的步驟指名它時才會被讀取。本程式不會上傳你硬碟裡的內容。

九、本機命令

command 步驟執行的，是你自己寫進任務規格的那一行命令，在你的電腦上、用你的 Windows 帳戶執行。本程式不會下載程式回來執行，也不會從網路上抓程式碼來跑。高風險動作會先停下來等你批准；超出授予權限等級的動作會被拒絕，而且不產生任何副作用。

十、即時生成式 AI

agent 步驟會依你的 prompt，由模型即時產生文字。你看到的生成內容沒有經過開發者事先審閱，可能不正確、可能冒犯人，也可能不適合你的用途。不要不檢查就直接採用。

你可以直接在程式裡回報不當的 AI 生成內容：主畫面 →「隱私、支援與回報」→「回報不當的 AI 產出」。選一個理由，可以補上該次執行編號與步驟編號、再寫幾句說明，然後按「先看會送出什麼」，在任何東西被寫下來之前先把整份內容看過。

一筆回報只帶編號：回報編號、時間、程式版本、理由、執行編號、步驟編號，以及你寫的說明。沒有 prompt、沒有檔案內容、沒有完整對話、沒有憑證。你寫的說明還會再洗一次 —— 看起來像 API 金鑰、電子郵件、網址、Windows 或 UNC 路徑的片段，以及過長的連續字串，一律換掉，超過 500 字截斷；洗掉了什麼會列給你看。

回報會寫成資料夾裡 reports\ 的一個檔案。這一版沒有回報伺服器，所以不會有任何東西被送出去：要不要把那個檔寄到支援信箱，由你決定。支援頁寫著同一條路，給打不開程式的人看。

十一、資料分享與販售

開發者收不到任何使用者資料，因此沒有東西可以分享，也沒有東西可以販售。資料只會去你自己在任務規格裡指名的目的地。

十二、保存與刪除

全部存在本機，而且會一直留著，直到你自己刪掉。刪掉資料夾就等於刪掉全部的程式資料，包含 Vault、執行紀錄、費用帳本與產物。備份還原是手動的，由你自己觸發；備份寫到你指定的位置。伺服器端沒有副本，所以也沒有「請開發者刪除」這件事。

十三、你可以控制的事

  • 隨時刪掉整個資料夾，或裡面的任何一個檔案。
  • 移除或輪換任何一筆已存的憑證。
  • 決定一個任務裡有哪些步驟。你沒寫的步驟永遠不會跑。
  • 在批准閘門逐項批准或拒絕高風險動作。
  • 保持無人值守模式關閉，它預設就是關的。無人值守可以排程、額度回來自動再試、崩潰自動續跑，但它不批准任何事 —— 跑到要批准就會停。
  • 設定預算上限，讓一趟執行在你指定的金額停下來。
  • 隨時打開「隱私、支援與回報」，看你這一版實際算出來的結果：哪幾種步驟會把東西送出這台機器、送去哪裡、哪些資料只留在本機、哪些是加密的。
  • 回報你認為不當的 AI 產出，而且在它被寫下來之前先看過整份內容。

十四、兒童

ai-team-os 是開發者工具，並非針對兒童設計。你自行設定的第三方服務各有年齡限制，是否符合由你自己負責。

十五、政策更新

本程式的資料處理方式一有更動，這一頁就會更新。頁面最上方的最後更新日期就是最近一次更動的日期。

十六、聯絡方式

電子郵件：linsevenlight@gmail.com

隱私問題、安全漏洞回報與一般支援都用同一個信箱。來信請不要附上 API 金鑰、存取 token、密碼或機密專案內容。
