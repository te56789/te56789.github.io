English

In one paragraph. ai-team-os runs entirely on your own Windows PC. There is no account, no sign-in, no developer-operated server and no telemetry — the developer receives no data from the application at all. Data leaves your computer only in ways you set up yourself: a task step you wrote, a chat you send to a cloud model, notifications you switched on, or an update check against an address you entered. Each one goes only to the destination you chose. Everything else stays in one local folder that you can delete at any time.

1. Scope

ai-team-os ("the application") is a Windows desktop application published by te56789. This policy describes how the application handles data on the user's own device. It applies to the copy distributed through the Microsoft Store and to builds distributed from the project's public releases repository.

2. No accounts, no cloud service

The application has no sign-in, no user account and no developer-operated server. The developer does not host, receive or store user content. There is no cloud sync, no multi-user collaboration and no remote administration.

3. No telemetry

The application sends no usage data, analytics, crash reports or diagnostic pings to the developer. The telemetry package in the source tree is intentionally empty. There is no analytics setting to turn off, because nothing is collected.

4. What is stored on your device

All application data lives in one local data folder. By default that folder is %APPDATA%\ai-team-os for the installer build, and %USERPROFILE%\.ai-team-os for the Microsoft Store (MSIX) build — the Store build deliberately keeps its data outside %APPDATA% so that uninstalling the app never deletes it. You can move it by setting the TEAMOS_HOME environment variable. The folder contains:

  • vault\ — stored credentials (API keys, the notification webhook address, a GitHub token), encrypted with Windows DPAPI under your Windows user account;
  • runs\runs.db — run records, step events, the cost ledger, task-specification versions, notices and the list of artifacts;
  • registry.db — the workspaces and projects you have registered;
  • memory.db — cross-task memory: what the platform remembers and where each item came from. It can contain text read back from websites you automate, such as error messages and excerpts of results;
  • modules\feature.chat\data.db — your conversations with AI models: what you typed, the replies, the text of attached files, and which model each message used and what it cost. Anything you paste into a conversation is kept here;
  • modules\feature.roundtable\data.db — roundtable decision records;
  • modules\feature.automation\data.db — the unattended-mode ledger and the notifications it sent, including the ones that failed;
  • artifacts\ — the content of files produced by task steps;
  • browser-profiles\ — browser sign-in state used by browser steps, encrypted with Windows DPAPI;
  • recorded\ — task drafts recorded in the browser, in plain text. They can contain values you typed into form fields; password fields are never recorded;
  • logs\ — fault logs. Strings that look like keys are masked before anything is written, but task titles and error messages can appear;
  • platform.json and modules.json — application settings, and which modules you have switched off;
  • reports\ — the reports you create with “Report inappropriate AI output”, one JSON file each. They stay on your device until you choose to send one.

The application never uploads this folder. Pieces of it travel only along the routes listed in section 5: for example, the earlier messages of a conversation go with your next chat message, and when memory is switched on, remembered items relevant to a task go with an agent step's prompt.

5. What can leave your device, and only when you ask for it

A task specification is data that you author: you define the steps in the task builder or import them as JSON, and the application executes them. Four step kinds can send something off the machine, and each one sends it to a destination that you wrote into your own specification or chose yourself.

Step kindWhat is sentWhere it goes
agent The step's instructions, the content of the files and diffs that seat can read, and, when memory is switched on, the remembered items relevant to the task. The model service you chose for that step. A local Ollama model, which the built-in templates use by default, keeps all of this on your computer. A cloud model is used only if you pick one and store its API key; the data then goes to that provider.
http The request you defined in the step. The URL you wrote in the specification.
browser The navigation, and whatever the six permitted verbs do on the page you named. The host you wrote in the specification. Three separate host-allowlist checks run before a navigation is performed.
push The commits that the remote does not have yet: file contents, commit messages, and author names and e-mail addresses. The git remote you set up in git. The specification can refer to it only by name (for example origin). Every push stops for your approval, and the approval shows the remote's address with any credentials masked.

A few features are not task steps but can also send data off the machine:

FeatureWhat is sentWhere it goes
Chat What you type, the text of files you attach, and the earlier messages of that conversation; if you tick “include memory”, also the remembered items. The model you picked for that conversation. A local Ollama model keeps it on your computer; a cloud model sends it to that provider.
Notifications (off by default) Notices from unattended mode about runs that need you: the notice's title and text, which name the task concerned, plus its run id unless your message template leaves it out. The webhook address you stored, for example a Telegram, Slack or Discord endpoint.
Update check (off by default) A request for the update description file, made when you press the check button. It carries nothing about you or your tasks. The update source address you entered in settings. While that field is empty, which is the default, the application never checks. The Microsoft Store build is updated by the Store.

What is sent is what you put there yourself: prompt text, the files and project context you selected, your messages. The application does not scan your drive, does not upload files you did not reference, and sends nothing beyond what these two tables list.

6. Credentials

Credentials are held in a local vault encrypted with Windows DPAPI and tied to your Windows user account. The vault supports three profile layers — system, user and project — and credential rotation. Plaintext secrets are never written to logs, never rendered in the user interface and never placed on a command line.

You may choose to store credentials for third-party services. The kinds of credential the vault can hold include API keys for DeepSeek, Meta/Llama, DashScope/Qwen, Z.ai/GLM, Gemini, OpenAI and Anthropic services, notification webhook URLs of the kind used by Telegram or Slack, and a GitHub token. A webhook URL is itself a secret and is stored as one. The GitHub token is used only by a command-line tool that exists when the application is run from source, which posts a redacted handoff package to a GitHub issue or pull request you name; the Microsoft Store and installer builds do not use it.

None of these services is enabled by default, and ai-team-os is not affiliated with, endorsed by, or an official client of any of them. Storing a credential does not by itself transmit anything: a credential is used only when a step you wrote calls the service it belongs to.

7. Third-party services you configure

When a step you wrote sends data to a third-party service, that service's own terms and privacy policy govern what happens to the data. Review them before configuring a service. The developer of ai-team-os has no visibility into and no control over that processing.

8. Files

The application reads and writes files inside the projects you register and inside its own data folder. A write_file step writes where the specification says to write. A git_commit step commits in the git worktree assigned to that seat. Files are read only when a step you wrote refers to them. The application never uploads the contents of your drive.

9. Local commands

A command step runs a command line that you wrote into the task specification, on your machine, under your Windows account. The application does not download programs and run them, and does not fetch code from the internet to execute. High-risk actions stop and wait for your approval before running; an action beyond its granted permission level is refused and produces no side effect.

A command step can start only programs on the built-in allow-list, and running a script, or any interpreter command that could execute code, needs your approval. If the program itself uses the network, as git fetch or npm install do, it contacts the address it is set up for; the application adds no data of its own.

10. Live generative AI

An agent step or a chat produces text generated by a model in response to your prompt. Generated output is not reviewed by the developer before you see it, and it can be inaccurate, offensive or otherwise unsuitable. Do not rely on generated output without checking it.

You can report inappropriate AI-generated content from inside the application: main window → Privacy, support and reporting → Report inappropriate AI output. Pick a reason, optionally add the run and step identifiers and a short note, then press preview what will be sent to read the exact payload before anything is written.

A report carries identifiers only — report id, timestamp, application version, reason, run id, step id and your note. It carries no prompt, no file content, no conversation and no credential. Your note is additionally scrubbed of anything that looks like an API key, an e-mail address, a URL, a Windows or UNC path, or a long unbroken string, and it is truncated at 500 characters; the application shows you what it removed.

The report is written as a file in reports\ inside your data folder. This release has no reporting server, so nothing is transmitted: you decide whether to send that file to the support address. The support page describes the same route for anyone who cannot open the application.

11. Data sharing and sale

The developer receives no user data, and therefore shares none and sells none. Data goes only to the destinations you chose, as listed in section 5.

12. Retention and deletion

Everything is kept locally, and kept until you delete it. Deleting the data folder removes all application data, including the vault, run history, cost ledger and artifacts. Backup and restore is manual and is triggered by you; a backup is written where you tell the application to write it. There is no server-side copy for you to request the deletion of.

13. Your controls

  • Delete the data folder, or any file inside it, at any time.
  • Remove or rotate any stored credential.
  • Decide which steps exist in a task. A step you do not write never runs.
  • Approve or refuse each high-risk action at the approval gate.
  • Leave unattended mode off; it is off by default. Unattended mode can schedule work, retry when quota returns and resume after a crash, but it approves nothing — it stops at every approval gate.
  • Set a budget ceiling so a run stops at a cost you chose.
  • Pick local Ollama models for agent steps and chat, and your prompts never leave your computer.
  • Notifications and the update check are off by default; turn them on only if you want them.
  • Switch off features you do not use under Settings → Modules.
  • Open Privacy, support and reporting at any time to see, for the build you are running, where its data is kept on this machine, which of it is encrypted, and which step kinds can send data off it.
  • Report AI output you consider inappropriate, and read the exact payload before it is written.

14. Children

ai-team-os is a developer tool and is not directed to children. Third-party services you configure have their own age requirements, which you are responsible for meeting.

15. Changes to this policy

This page is updated when the application's data handling changes. The Last updated date at the top of the page reflects the most recent change.

16. Contact

Email: linsevenlight@gmail.com

Use the same address for privacy questions, security reports and general support. Please do not include API keys, access tokens, passwords or confidential project content in any message.

一、適用範圍

ai-team-os（以下稱「本程式」）是 te56789 發行的 Windows 桌面應用程式。本政策說明本程式在使用者自己的電腦上怎麼處理資料，適用於 Microsoft Store 通路的版本，以及本專案公開釋出倉庫發佈的版本。

二、沒有帳號，也沒有雲端服務

本程式沒有登入、沒有使用者帳號，開發者也沒有架設任何伺服器。開發者不代管、不接收、不保存使用者的內容。沒有雲端同步、沒有多人協作、沒有遠端管理。

三、沒有遙測

本程式不會把使用資料、分析數據、當機報告或診斷訊號送回給開發者。原始碼裡的 telemetry 套件是刻意留空的。這裡沒有「關閉分析」的開關，因為根本沒有收集。

四、存在你電腦裡的東西

本程式的資料全部放在同一個本機資料夾。安裝檔版本的預設位置是 %APPDATA%\ai-team-os；Microsoft Store（MSIX）版本則是 %USERPROFILE%\.ai-team-os —— 商店版刻意把資料放在 %APPDATA% 之外，這樣解除安裝就不會把它一起刪掉。你可以設定 TEAMOS_HOME 環境變數把它搬到別的地方。這個資料夾裡有：

  • vault\ —— 已儲存的憑證（API 金鑰、通知用的 webhook 網址、GitHub token），用 Windows DPAPI 綁你的 Windows 使用者帳戶加密；
  • runs\runs.db —— 執行紀錄、步驟事件、費用帳本、任務規格的版本、通知，以及產物清單；
  • registry.db —— 你登記過的工作區與專案；
  • memory.db —— 跨任務的記憶：平台記住的事，以及每一條的來源。裡面可能有從你自動化的網站上讀回來的文字，例如錯誤訊息和產物片段；
  • modules\feature.chat\data.db —— 你跟 AI 模型的對話：你打的字、模型的回覆、附件的文字內容，以及每一則用了哪個模型、花了多少錢。你貼進對話的任何東西都會存在這裡；
  • modules\feature.roundtable\data.db —— 圓桌的決策紀錄；
  • modules\feature.automation\data.db —— 無人值守的帳，以及它送過的通知（送不出去的也記）；
  • artifacts\ —— 任務步驟產生的檔案內容；
  • browser-profiles\ —— browser 步驟用的瀏覽器登入狀態，同樣用 Windows DPAPI 加密；
  • recorded\ —— 在瀏覽器上錄出來的任務草稿，純文字。裡面可能有你在表單欄位打過的值；密碼欄位一律不記；
  • logs\ —— 故障紀錄。寫進去之前會先遮掉長得像金鑰的字串，但任務標題和錯誤訊息可能還在；
  • platform.json 與 modules.json —— 程式設定，以及你關掉了哪些模組；
  • reports\ —— 你用「回報不當的 AI 產出」建立的回報，一筆一個 JSON 檔。在你決定寄出之前，它們只待在你的電腦裡。

本程式不會把這個資料夾上傳到任何地方。裡面的資料只會沿著第五節列的路線送出，例如繼續一段對話時，前面的訊息會跟著新訊息一起送出；記憶打開時，跟任務有關的記憶會跟著 agent 步驟的 prompt 一起送出。

五、什麼會離開這台電腦，而且只在你叫它送的時候

任務規格是你自己寫的資料：你在「任務建立」畫面定義步驟，或是匯入 JSON，本程式負責照著執行。有四種步驟會把東西送出這台機器，每一種都只送到你自己在規格裡寫的、或自己選的目的地。

步驟種類送出什麼送去哪裡
agent 步驟裡的指示、這個席次讀得到的檔案內容與 diff；記憶打開時，再加上跟這個任務有關的記憶。 你替這個步驟選的模型服務。用本機 Ollama 模型（內建範本預設就是）的話，這些資料都不會離開這台電腦。只有你自己選了雲端模型、也存了它的 API 金鑰，資料才會送到那一家。
http 你在步驟裡定義的那個請求。 你在規格裡寫的那個網址。
browser 導向動作，以及六個許可動詞在你指定的頁面上做的事。 你在規格裡寫的主機。導向之前會先過三道主機清單檢查。
push 遠端還沒有的那幾個 commit：檔案內容、commit 訊息、作者名字與 email。 你在 git 裡設定好的遠端。規格裡只能寫遠端的名字（例如 origin）。每一次推送都要你批准，批准畫面會顯示遠端網址，裡面的帳密會遮掉。

另外有幾個功能不是任務步驟，但一樣會把資料送出這台機器：

功能送出什麼送去哪裡
對話 你打的字、附加檔案的文字內容、這段對話前面的訊息；勾了「帶記憶」的話，再加上平台記得的事。 你替這段對話選的模型。本機 Ollama 模型不會離開這台電腦；雲端模型就送到那一家。
通知（預設關閉） 無人值守遇到需要你處理的狀況時發的通知：通知的標題與內容，裡面會寫是哪一個任務；除非你的訊息樣板沒放，否則也會帶執行編號。 你存的 webhook 網址，例如 Telegram、Slack 或 Discord 的收件端。
檢查更新（預設關閉） 你按下檢查按鈕時發出的一個請求，只讀取更新說明檔，不帶任何關於你或你的任務的資料。 你在設定裡填的更新來源網址。這一格空著（預設就是空的）的時候，本程式從不檢查。Microsoft Store 版本由 Store 負責更新。

送出去的內容，就是你自己放進去的內容：prompt 文字、你挑的檔案和專案上下文、你打的訊息。本程式不會掃你的硬碟，不會上傳你沒有指名的檔案，也不會送出上面兩張表以外的東西。

六、憑證

憑證放在本機的 Vault，用 Windows DPAPI 加密，綁定你的 Windows 使用者帳戶。Vault 支援 system、user、project 三層 profile，也支援輪換。明文祕密不會寫進 log、不會顯示在畫面上、不會出現在命令列。

你可以自行選擇要不要存第三方服務的憑證。Vault 能存的憑證種類包含 DeepSeek、Meta/Llama、DashScope/Qwen、Z.ai/GLM、Gemini、OpenAI、Anthropic 等服務的 API 金鑰、Telegram、Slack 這一類的通知 webhook 網址，以及 GitHub token。webhook 網址本身就是祕密，所以也當祕密存。GitHub token 只有從原始碼執行時才有的一個命令列工具會用到：它把遮蔽過的交接包貼到你指定的 GitHub issue 或 pull request。Microsoft Store 與安裝檔版本不會用到它。

上面這些服務沒有一個是預設啟用的。ai-team-os 與其中任何一家都沒有隸屬、合作或官方授權關係，也不是任何一家的官方用戶端。存了憑證不等於送出任何東西：憑證只有在你寫的步驟去呼叫它所屬的服務時才會被用到。

七、你自己設定的第三方服務

當你寫的步驟把資料送到第三方服務時，那筆資料之後怎麼處理，由該服務自己的條款與隱私權政策決定。設定前請先讀過。ai-team-os 的開發者看不到也管不到那一段處理。

八、檔案

本程式會在你登記的專案內，以及自己的資料夾內讀寫檔案。write_file 步驟寫在規格指定的位置；git_commit 步驟在那個席次被分配到的 git worktree 裡 commit。檔案只有在你寫的步驟指名它時才會被讀取。本程式不會上傳你硬碟裡的內容。

九、本機命令

command 步驟執行的，是你自己寫進任務規格的那一行命令，在你的電腦上、用你的 Windows 帳戶執行。本程式不會下載程式回來執行，也不會從網路上抓程式碼來跑。高風險動作會先停下來等你批准；超出授予權限等級的動作會被拒絕，而且不產生任何副作用。

command 步驟只能啟動內建允許清單上的程式；執行腳本，或任何可能跑程式碼的直譯器命令，都要你批准。如果那支程式自己會連網路，像 git fetch 或 npm install，它連的是它自己設定的位址，本程式不會另外加資料進去。

十、即時生成式 AI

agent 步驟和對話會依你的 prompt，由模型即時產生文字。你看到的生成內容沒有經過開發者事先審閱，可能不正確、可能冒犯人，也可能不適合你的用途。不要不檢查就直接採用。

你可以直接在程式裡回報不當的 AI 生成內容：主畫面 →「隱私、支援與回報」→「回報不當的 AI 產出」。選一個理由，可以補上該次執行編號與步驟編號、再寫幾句說明，然後按「先看會送出什麼」，在任何東西被寫下來之前先把整份內容看過。

一筆回報只帶編號：回報編號、時間、程式版本、理由、執行編號、步驟編號，以及你寫的說明。沒有 prompt、沒有檔案內容、沒有完整對話、沒有憑證。你寫的說明還會再洗一次 —— 看起來像 API 金鑰、電子郵件、網址、Windows 或 UNC 路徑的片段，以及過長的連續字串，一律換掉，超過 500 字截斷；洗掉了什麼會列給你看。

回報會寫成資料夾裡 reports\ 的一個檔案。這一版沒有回報伺服器，所以不會有任何東西被送出去：要不要把那個檔寄到支援信箱，由你決定。支援頁寫著同一條路，給打不開程式的人看。

十一、資料分享與販售

開發者收不到任何使用者資料，因此沒有東西可以分享，也沒有東西可以販售。資料只會去第五節列的、你自己選的目的地。

十二、保存與刪除

全部存在本機，而且會一直留著，直到你自己刪掉。刪掉資料夾就等於刪掉全部的程式資料，包含 Vault、執行紀錄、費用帳本與產物。備份還原是手動的，由你自己觸發；備份寫到你指定的位置。伺服器端沒有副本，所以也沒有「請開發者刪除」這件事。

十三、你可以控制的事

  • 隨時刪掉整個資料夾，或裡面的任何一個檔案。
  • 移除或輪換任何一筆已存的憑證。
  • 決定一個任務裡有哪些步驟。你沒寫的步驟永遠不會跑。
  • 在批准閘門逐項批准或拒絕高風險動作。
  • 保持無人值守模式關閉，它預設就是關的。無人值守可以排程、額度回來自動再試、崩潰自動續跑，但它不批准任何事 —— 跑到要批准就會停。
  • 設定預算上限，讓一趟執行在你指定的金額停下來。
  • 替 agent 步驟和對話選本機 Ollama 模型，你的 prompt 就不會離開這台電腦。
  • 通知和檢查更新預設都是關的，需要再打開。
  • 在「設定 → 模組」關掉用不到的功能。
  • 隨時打開「隱私、支援與回報」，看你這一版實際算出來的結果：資料放在這台電腦的哪裡、哪些是加密的、哪幾種步驟會把東西送出這台機器。
  • 回報你認為不當的 AI 產出，而且在它被寫下來之前先看過整份內容。
